# Фреймворк — механизмы, а приложение — всё предметное

Приложение даёт скриптам своё API, а cliche делает из скриптов на JavaScript команды его CLI. Здесь решено, где
проходит граница и каким Go-API она выражена. Первый потребитель — ytrack: его поведение через `Run` не меняется.

## Граница

- **cliche знает только механизмы:** источники и каталог скриптов, объявление команды и его чтение без выполнения,
  команды cobra из объявления, разбор вызова, справку и подсказки скриптовых команд, движок goja, мост значений и
  ошибок Go↔JS, подмножество Node.
- **Приложение владеет:** модулями API и их именами, типами флагов сверх базовых, печатью ответа, кодами ошибок и
  кодами возврата, входом, своими Go-командами, `--version`, командой `completion`, политикой версий API и строгими
  правилами корней.
- **Публичного рантайма JS нет.** Всё, что приложение даёт скрипту, оно даёт через модуль API. Колбэков из Go в JS,
  долгоживущей среды, цикла событий и `Promise` нет.

## Исполнение

- goja, CommonJS (`require`, `exports`, `module`), строгий режим, синхронно. Среда создаётся на каждый `Run`;
  отмена контекста прерывает скрипт; стек вызовов ограничен.
- Песочницы нет: скрипту доверяют как репозиторию, в котором он лежит.
- `require` принимает путь с `./` или `../` внутри своего источника, имя модуля из `Env.Modules` и модули
  подмножества Node, которые включило приложение. Модуль с объявлением команды не подключается: команда не зовёт
  команду.

## Источники и каталог

```go
func Dir(path string) Source             // файл называется абсолютным путём внутри каталога
func FS(name string, fsys fs.FS) Source  // файл называется "<name>:<путь>"
func DefaultSources(app, workingDir, home string) []Source

type Config struct {
	Name    string           // .<Name>/scripts
	Builtin fs.FS            // вшитые скрипты, всегда первые; файл называется "builtin:<путь>"
	Sources []Source         // nil — DefaultSources(Name, os.Getwd(), os.UserHomeDir()); пустой — внешних нет
	Types   map[string]Type  // типы приложения сверх базовых
}
```

- `DefaultSources`: ближайший `.<app>/scripts` вверх от `workingDir` и `<home>/.<app>/scripts`. Если ближайший над
  каталогом вызова — пользовательский, корня проекта нет. Пустой `workingDir` или `home` — нет и соответствующего
  корня. Существующий путь, который не читается, — источник со своей ошибкой, а не пропуск.
- Путь файла — путь команды: `docs/map.js` — `docs map`. Файл без объявления — библиотечный модуль. Каталог, под
  которым есть команда, — группа. Файл и каталог с точкой в начале не читаются; каталог на восьмом слове пути — сломанный путь. `x.js` и
  каталог `x/` с командами вместе — сломанный путь. Слово пути — строчные буквы, цифры, `-` и `_`, не с `-` и `_`.
- `Config.Scan()` отдаёт корни по порядку, у каждого — первые слова пути с их командами, сломанными путями и
  названием файла или каталога. Приложение с собственным правилом конфликтов (ytrack: первое слово — одному корню,
  встроенную команду нельзя заменить) решает по ним само.
- `Merge(roots)` — правило по умолчанию: при совпадении полного пути команды побеждает корень раньше, о проигравшем —
  предупреждение. `docs` одного корня и `docs map` другого не конфликтуют: cobra держит команду с подкомандами.
  Сломанные пути и нечитаемые корни — данные каталога; печатает их приложение.
- `Catalog.AddTo(root, run)` ставит команды каталога под корень cobra: группу на слово, которого у корня нет, скрытую
  команду на сломанный путь. Группа без известной подкоманды — `*UsageError`; группа только сломанных путей скрыта.
  Приложение со своим деревом собирает его из `Command.Cobra` само.

## Объявление

- `exports.definition` — чистый литерал: строки, строки через `+`, числа, `true`, `false`, `null`, массивы,
  объекты; без имён, вызовов и вычислений. Неизвестный ключ на любом уровне делает объявление нечитаемым. `short`
  (одна строка до 60 символов) и `long` обязательны.
- **Аргумент** — `{ name, type, usage }` или группа `{ name, usage, group: [слот, ...] }`, где слот —
  `{ name, type, usage }`. Признаки `optional: true` и `multiple: true` (один или больше). Переменным — `optional`
  или `multiple` — может быть не больше одного элемента: элементы до него разбираются слева, после — справа, середина
  достаётся ему и у группы делится на её ширину. Два переменных элемента — нечитаемое объявление.
- Команда получает аргументы в объявленном порядке: одиночный — значение, группа — запись `{ слот: значение }`,
  `multiple` — массив, не данный `optional` — `Undefined{}` в `Input.Args` и `undefined` у команды; значение `nil`,
  которое вернул `Parse`, — `null`. Последний аргумент — объект флагов, всегда.
- **Флаг** — `{ name, type, usage, multiple?, choices?, default? }`. Разбор строгий: неизвестный флаг, значение вне
  `choices`, лишний или недостающий токен, значение, которое не разбирает тип, — ошибка до запуска скрипта.
- **Базовые типы:** `string`, `path` (подсказка — имя файла), `int` (32 бита), `bool` (только флаг), `pair`
  (`Name=value`; флаг `multiple` собирает имена в объект, повторённое имя — в массив), `duration` (ISO 8601 часов и
  минут в целые минуты). `multiple` — у `string` и `pair`; `choices` — у `string`; у `pair` и `duration` нет
  `default`.
- **Тип приложения:**

```go
type Type struct {
	Usage   string                         // фиксированная строка справки; объявление её не пишет
	Default bool                           // default обязателен
	Parse   func(text string) (any, error) // каждое значение вызова
	Value   func(def any, given []any) any // что получает command; nil — ключа нет
}
```

- `Value` — правило флага; аргумент и слот получают то, что вернул `Parse`, и повторяются группой или `multiple`
  аргумента с любым типом. У флага `multiple` и `choices` типа приложения
  нет, как и у прочих типов, кроме `string` и `pair`.

## Мост значений

```go
type Map interface { Keys() []string; Get(key string) (any, bool) }
type List interface { Len() int; Index(i int) any }
type Object struct{ /* ключи в порядке */ }  // NewObject(keys, values), Keys(), Get(key)
type Func func(ctx context.Context, args ...any) (any, error)
type Getter func(ctx context.Context) (any, error) // свойство, которое считается при чтении
```

- Значение моста: `nil` (`null`), `bool`, `string`, `int64`, `float64`, `*big.Int`, `[]byte`, `[]any`, `*Object`,
  `Map`, `List`, `Func`, `Getter`. Целое вне ±2^53 уходит в JS как `BigInt`; `[]byte` — копия в `Buffer`.
- `Map`, `List` и `*Object` из Go видны скрипту только для чтения в порядке ключей; запись, добавление, удаление и
  `push` бросают `TypeError`. Повторное чтение отдаёт тот же JS-объект.
- `Map`, `List` или `Func`, вернувшийся из скрипта или переданный в `Func`, — в том числе вложенным, — приходит в Go
  тем же значением. Построенное скриптом приходит как `*Object` (ключ со значением `undefined` опущен), `[]any`,
  скаляры; целое число — `int64`, дробное — `float64`, `BigInt` — `*big.Int`, `Buffer`, `Uint8Array` и
  `ArrayBuffer` — копия `[]byte`. Функция, символ, `Date` и прочие объекты своего класса — ошибка с местом в значении.
  Getter-свойства читаются под перехватом исключений VM.
- `Place(ctx) (file string, line, column int)` в `Func` — строка скрипта, которая её вызвала.

## Ошибки

- Ошибка `Func` бросается в JS объектом только для чтения с прототипом `Error`. Поля — `ScriptFields() Map` ошибки
  (через `errors.As`), иначе `message`; `message` есть всегда.
- Непойманная или переброшенная (`throw e`) ошибка приложения возвращается из `Run` той же Go-ошибкой. Ошибка,
  построенная скриптом, — даже с полями, скопированными с ошибки приложения, — ошибка скрипта.
- Свои ошибки cliche — типы: `*ScriptError` (сообщение, файл, строка, колонка; нечитаемое объявление и сломанный путь —
  тоже он; ошибка без кадра скрипта, например при чтении возвращённого значения, называет файл скрипта команды), `*UsageError` (вызов не разобран), `*FileError` (непойманная ошибка `fs`: код, syscall, путь),
  `*FetchError` (адрес и причина), `*InterruptedError` (отмена контекста). `Env.Error`, если задан, переводит
  ошибку cliche, которую скрипт может поймать (`*FetchError`), в ошибку приложения перед броском.
- Код ошибки, документ в stderr и код возврата решает приложение. Встроенный ли скрипт, говорит `Command.Builtin()`.

## Запуск

```go
func (c *Catalog) AddTo(root *cobra.Command, run func(cmd *cobra.Command, c *Command, in Input) error)
func (c *Command) Cobra(run func(cmd *cobra.Command, in Input) error) *cobra.Command
func Run(ctx context.Context, c *Command, in Input, env Env) (any, error)

type Env struct {
	Modules map[string]any   // require(имя)
	Node    Node             // NodeFS | NodeFetch | NodeBuffer; без них скрипт их не видит
	Error   func(error) error
}
```

- `Cobra` строит `Use`, `Short`, `Long` с разделом `Arguments:`, флаги pflag, проверку числа аргументов и подсказки
  cobra (`path` — имена файлов, `choices` — набор). `run` получает разобранный вызов; печатает ответ приложение.
- Подмножество Node — как в ADR-0012 ytrack: `fs` (`*Sync`), `Buffer`, `fetch` только `GET`, синхронно; опция,
  которой нет, — `TypeError`.

## Отвергнуто

- **Публичный рантайм JS и колбэки из Go.** Протокол приложения обслуживает Go-код приложения; скрипт передаёт данные.
- **Тип документа, словарь кодов, правило кодов возврата и формат вывода во фреймворке.** Это решения приложения.
- **Частичный разбор аргументов, `min`/`max`, несколько переменных элементов.** Терпимость к битой записи скрипт
  получает, объявив слоты `string`.
- **Версии API во фреймворке.** `ytrack/v1` — просто имя модуля.
