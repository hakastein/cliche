# Промисы goja и цикл движка

Скрипту нужна асинхронность обычного JS: приложение даёт функции, которые работают минуты (этап агента), и скрипт
запускает их параллельно — `await Promise.all([api.agent(a), api.agent(b)])` — и ждёт событий запущенной работы.
Здесь решено, как Go-работа приложения становится промисом скрипта, как `Run` ждёт его и как работает отмена.
Целевой сценарий — работа, которую приложение запускает в своей горутине и о ходе которой сообщает промисами:
синхронная `Func` возвращает `{started, result}`, скрипт делает `await run.started; await run.result`.

## API

```go
// В своей горутине; скрипт получает промис того, что она вернула.
type Async func(ctx context.Context, args ...any) (any, error)

// Промис, который приложение разрешает из любой горутины; нулевое значение ожидает.
type Promise struct{ /* … */ }
func (p *Promise) Settle(value any, err error)
```

## Модель

- Промисы, `async`/`await` и очередь заданий промисов — goja: задания выполняются, когда вызов из Go в рантайм
  возвращается. Рантайм однопоточный, поэтому горутины его не трогают: разрешение кладут в очередь движка, не
  блокируясь, а `Run` выполняет очередь на своей горутине по порядку. Это и есть цикл.
- **Вызов `Async`.** Аргументы переводятся мостом при вызове, как у `Func`; функция идёт в своей горутине с
  контекстом вызова (`Place` в нём), скрипт сразу получает промис. Значение и ошибку переводит тот же мост на цикле:
  ошибка отклоняет промис тем же объектом, который бросил бы `Func`, значение, которого мост не несёт, — `TypeError`.
- **`*Promise`** — значение моста: скрипту — промис goja, обратно в Go — тот же `*Promise`. В силе первый `Settle`.
  События и итог запущенной работы так и передаются: `Func` запускает работу в горутине приложения и отдаёт объект
  с промисами-полями, работа разрешает их по ходу, скрипт их ждёт.
- **Команда.** `exports.command` может вернуть промис (`async`): `Run` крутит цикл до его разрешения. Выполненный
  отдаёт значение по правилам моста; отклонённый — как исключение: ошибка приложения — та же Go-ошибка, ошибка скрипта
  — `*ScriptError` с местом создания `Error`.
- **Источники разрешения** — идущие вызовы `Async` и неразрешённые `*Promise`, которые запуск отдал скрипту.
  Пока источник есть, а промис команды ждёт, `Run` ждёт очередь до отмены контекста.
- **Зависание.** Очередь пуста, промис команды ждёт, а источников нет — разрешить его некому: `*ScriptError` вместо
  вечного ожидания. `*Promise`, который приложение не разрешит никогда, cliche от ещё не разрешённого не отличает:
  такой запуск ждёт до отмены контекста.

## Отмена

- Контекст `Async` — контекст `Run`. Отмена прерывает и скрипт, и ожидание цикла: `*InterruptedError` с причиной
  контекста.
- Возвращаясь — с ответом, ошибкой или по отмене, — `Run` отменяет контекст работы, которую команда не дождалась, и
  ждёт конца всех горутин `Async`: после `Run` горутин cliche нет. Функция `Async` завершается по отмене `ctx`, иначе
  `Run` ждёт её.
- Горутины приложения `Run` не ждёт. Контекст `Func` — тот же контекст `Run`, отменённый на выходе из `Run`: горутина,
  запущенная с ним, завершается по отмене.
- Возвращаясь, `Run` снимает подписки запуска на неразрешённые `*Promise`: промис, который приложение держит дольше
  запуска, не держит его рантайм и модули. Разрешение после конца `Run` никуда не идёт и никого не блокирует.

## Отвергнуто

- **Цикл `goja_nodejs/eventloop`.** Он создаёт свой рантайм с глобальными `require`, `console` и таймерами в обход
  CommonJS и белого списка модулей (ADR-0001) и не знает о внешней работе: его `Run` выходит, когда нет таймеров.
  Счётчик работы, ожидание горутин и обнаружение зависания всё равно пришлось бы писать рядом; от него осталась бы
  очередь под мьютексом.
- **Источник — только `Async`.** Запуск, который ждёт промис из горутины приложения, падал бы ложным зависанием, и
  целевой сценарий пришлось бы оборачивать в `Async`, который только ждёт промисы.
- **Таймеры, `setTimeout`, отчёт о необработанных отклонениях.** Не нужны приложениям сейчас.
